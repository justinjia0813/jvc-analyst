# lustinus RESEARCH 行业研报生成 Skill 设计

日期：2026-07-21

状态：设计已确认，待用户审阅书面规格

## 1. 用户可见结果

创建 `/lustinus-research-report` skill。用户提供一份符合固定结构的行业研究 Markdown 文件及本地图片后，通过一条命令生成三项产物：

1. 可交付、可打印的 A4 PDF（Portable Document Format，可移植文档格式，用于固定页面布局并便于打印分发）报告；
2. 与 PDF 内容一致的 HTML（HyperText Markup Language，超文本标记语言，用于描述页面内容结构）预览；
3. 记录错误、警告、页数和检查结果的 `build-report.txt`。

报告使用 `lustinus RESEARCH` 品牌名。视觉语言借鉴国际投行研报的信息密度和层级秩序，但不使用其名称、标识或复制其模板。

## 2. 目标与边界

### 目标

- 将固定格式 Markdown 稳定编译为专业行业深度报告；
- 与现有 `/jvc-track-research` 的 0、A–I 研究骨架直接衔接；
- 将内容生成和版式生成分开，保证排版过程不改变研究判断；
- 允许复用少量品牌参数：机构名、标识、主题色、免责声明、页眉和页脚；
- 对输入错误和潜在版式问题给出明确、可行动的反馈。

### 第一版不做

- 不重写、压缩、补充或重新排序正文；
- 不联网补充事实或来源；
- 不从数据表自动生成图表；
- 不支持任意 Markdown 结构；
- 不建设多主题插件系统或逐页可视化编辑器；
- 不复刻高盛、摩根士丹利或其他机构的商标与专有模板。

## 3. 技术路线

采用以下单向生成链路：

```text
固定格式 Markdown + 本地图片 + 品牌配置
                    ↓
         解析、结构校验、资源校验
                    ↓
      markdown-it 生成 HTML 文档结构
                    ↓
   lustinus RESEARCH 打印样式与页面组件
                    ↓
          WeasyPrint 生成 A4 PDF
                    ↓
     PDF、HTML、build-report.txt
```

选择该路线的原因：当前环境已具备 `markdown-it` 和 WeasyPrint；WeasyPrint 对分页、页眉页脚、页码和中文打印样式的支持适合第一版，所需胶水代码也少于浏览器打印或 LaTeX 模板路线。

生成器只接受本地文件，不需要网络访问。HTML 是可检查的中间产物，不是第二套内容来源。

## 4. 输入契约

### 4.1 报告目录

```text
report-directory/
├── report.md
├── brand.yml
└── assets/
    ├── cover.png
    └── figure-01.png
```

`report.md` 是唯一正文来源。`brand.yml` 可跨报告复用。图片只允许通过相对路径引用，保证报告目录可以整体移动。

### 4.2 Markdown 元数据

`report.md` 使用 YAML（YAML Ain't Markup Language，YAML 不是标记语言，一种结构化元数据格式）frontmatter：

```yaml
---
title: 先进封装散热产业深度报告
subtitle: 从材料性能到客户预算
date: 2026-07-21
authors:
  - Justin
sector: 人工智能硬件
region: 中国及全球
classification: Internal
cover_image: assets/cover.png
disclaimer: Internal research only
---
```

必填字段仅为 `title` 和 `date`。其余字段缺失时使用空值或 `brand.yml` 中的默认值，并在构建报告中记录。

### 4.3 品牌配置

`brand.yml` 只开放已经确认的少量参数：

- `name`：默认且精确为 `lustinus RESEARCH`；
- `logo`：可选本地标识文件；
- `accent_color`：主题色；
- `header`、`footer`：页眉页脚文字；
- `disclaimer`：默认免责声明；
- `sans_font`、`serif_font`：字体名称或本地字体路径。

第一版不允许配置页面网格、任意组件或自定义脚本。

### 4.4 固定章节

报告正文按以下顺序组织：

1. `0. 研究设定与一页快照`
2. `A. 行业定义与边界`
3. `B. 行业简史与产业生命周期`
4. `C. 技术路线与商业可行性`
5. `D. 产业链图谱`
6. `E. 产业趋势、景气度与周期位置`
7. `F. 关键玩家分层`
8. `G. 监管、政策与标准`
9. `H. 投资相关问题`
10. `I. 后续工作交接包`
11. `来源索引`

0、A–I 的标题文字允许与 `/jvc-track-research` 保持一致的小幅变体，但章节编号、顺序和数量固定；来源索引固定放在 I 之后。校验器以章节编号识别 0、A–I，并单独识别来源索引，不依赖标题关键词猜测。

### 4.5 引用、图片和表格

- 正文来源引用使用 `[S1]`、`[S2]` 格式；
- `I. 来源索引` 必须包含每个已引用编号；
- 来源条目固定保留标题、机构或作者、日期、链接、来源类型和可信度；
- 第一版接受普通 Markdown 表格和本地图片；
- 生成器负责图表编号、题注、来源行、宽度限制和分页保护；
- 生成器不解释表中数据，也不根据数据自行选择图形。

## 5. 页面与组件设计

### 5.1 视觉语言

- 品牌名：`lustinus RESEARCH`；
- 主文字色：深灰黑；
- 强调色：克制的铜金色；
- 事实卡：绿色识别条；
- 推断卡：铜金色识别条；
- 未知或风险卡：红色识别条；
- 中文正文优先使用可嵌入的宋体，标题和数据优先使用可嵌入的黑体；
- 页面保持高信息密度，但用留白、标题层级和色条控制阅读压力。

若指定字体不可用，生成器直接报错，避免静默替换导致分页漂移。

### 5.2 首版组件

- 封面：报告标题、副标题、日期、作者、行业、地域、保密级别和可选封面图；
- 自动目录：章节标题、页码和内部链接；
- 章节首页：章节编号、标题和可选摘要；
- 关键结论条：承载一页快照中的 3–5 条判断；
- 事实卡：事实、数据和来源编号；
- 推断卡：机制、投资含义和置信度；
- 未知卡：证据缺口、反证条件和下一步动作；
- 表格与图片：自动编号、题注和来源；
- 页眉页脚：品牌名、报告标题、保密级别、日期和页码；
- 来源索引：按来源编号排版。

特殊卡片沿用 Markdown 引用块，并在首行使用 `[!FACT]`、`[!INFERENCE]` 或 `[!OPEN QUESTION]` 标记；未标记的正文继续使用标准 Markdown。该语法只负责选择版式，不允许携带执行代码。

## 6. 生成与失败行为

### 6.1 硬错误

遇到以下情况停止生成，不覆盖已有成功产物：

- 缺少 `title`、`date` 或固定章节；
- 固定章节缺失、重复或顺序错误；
- 图片路径失效或指定字体不可用；
- 正文引用了来源索引中不存在的 `[S<n>]`；
- 来源编号重复；
- Markdown 无法解析；
- WeasyPrint 渲染失败；
- 输出路径不可写。

错误信息必须包含文件、字段或来源编号以及修复提示。

### 6.2 警告

以下情况记录警告但继续生成：

- 缺少封面图或其他可选元数据；
- 图片分辨率偏低；
- 表格过宽、单元格文字过长；
- 标题、图片或表格可能产生不理想分页；
- 品牌配置中的可选值缺失并使用默认值。

生成器不通过修改正文来消除警告。

### 6.3 写入安全

生成过程先写入临时目录。只有解析、校验和 PDF 渲染全部成功后，才替换目标目录中的三项产物；失败时保留上一版成功结果。

## 7. 输出契约

默认输出目录包含：

```text
output/
├── report.pdf
├── report.html
└── build-report.txt
```

`build-report.txt` 至少记录：输入路径、生成时间、生成器版本、页数、错误、警告和各项检查结果。成功且没有警告时，也必须明确写出检查通过。

## 8. 验证与完成标准

实现完成前必须使用一个最小示例行业报告跑通完整链路，并满足：

1. 一条命令生成 PDF、HTML 和构建报告；
2. 自动目录、章节编号、图表编号、来源索引、页眉页脚和页码存在；
3. `pdfinfo` 能读取文件并返回合理页数；
4. `pdftotext` 提取结果包含标题、所有固定章节和来源索引；
5. `pdftoppm` 能渲染全部页面；
6. 人工检查渲染页，确认没有裁切、横向溢出、异常空白页、缺失内容、过密间距或风格不一致；
7. 无效示例能证明缺失章节、失效图片和未解析来源会阻止生成；
8. 构建失败不会覆盖上一版成功产物。

非平凡解析和校验逻辑保留一个最小、可重复运行的检查入口。第一版不建设大规模测试框架。

## 9. 建议的最小实现边界

实现应尽量复用现有运行环境，不新增模板引擎或前端框架。建议仅包含：

- `SKILL.md`：使用时机、输入要求、命令和停止规则；
- 一个 Python 构建脚本：解析、校验、生成 HTML、调用 WeasyPrint、写构建报告；
- 一个打印样式文件；
- 一个行业报告 Markdown 模板；
- 一个默认 `brand.yml`；
- 一个最小示例和一个可运行检查。

若上述文件可以安全合并，以更少文件为准；不为未来主题、图表生成或在线编辑预留抽象层。
