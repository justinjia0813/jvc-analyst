# jvc-analyst 2.0 共享研究内核设计

- 日期：2026-07-29
- 状态：已通过逐段设计确认，待实施
- 范围：`jvc-analyst` skill 包 2.0

## 1. 用户可见结果

`jvc-analyst` 2.0 保留现有 `/jvc-*` 调用方式，同时把关键研究从“仅依赖 prompt 遵守规则”升级为“prompt 负责判断、固定命令负责证据契约和完成闸门”。

Venture Capital（VC，风险投资）是围绕创业公司融资与投资判断开展的专业投资活动。本次升级覆盖完整投资研究链，不覆盖发票等行政流程。

用户完成一次研究后，应能获得：

- 原有 Markdown、工作簿或访谈纪要产物；
- 唯一事实源 `evidence_registry.jsonl`；
- 机器可读的 `audit.json`；
- 人可读的 `audit.md`；
- `ready`、`partial` 或 `blocked` 的明确研究状态；
- 每条重要主张对应的来源、反向证据、适用边界和剩余缺口。

JavaScript Object Notation（JSON，JavaScript 对象表示法）是一种结构化数据格式。JSON Lines（JSONL，逐行 JSON 数据格式）表示每行是一条独立 JSON 记录，适合增量登记、版本审查和确定性校验。

## 2. 成功标准

2.0.0 发布前必须满足：

1. 现有 `/jvc-*` 用户入口和主要输出格式保持兼容。
2. 所有接入研究内核的 skill 都声明并执行初始化与终审命令。
3. 未执行终审、终审结果过期或终审失败时，代理不得宣称研究完成。
4. 所有决策关键主张可追溯到证据、反向证据或明确的证据缺口。
5. 公司自述、第三方事实、用户观察、模型估算、代理推断和未知保持分离。
6. 关键来源冲突被保留并解释，不被平均或静默覆盖。
7. 用户批准的例外有原因、范围、批准者和剩余风险记录，且不能把不完整研究伪装成 `ready`。
8. 新旧非破坏性检查、安装模拟、真实端到端案例和发布前盲评全部完成。
9. 现有未提交修改和独立 worktree 不被覆盖或误提交。
10. `jvc-research-report` 只保留兼容接口，不成为本次发布依赖。

## 3. 非目标

2.0 不做以下事项：

- 不构建统一工作流引擎或自动替用户做投资决策。
- 不绑定具体搜索服务，不内置需要密钥或付费额度的联网脚本。
- 不完整镜像普通网页。
- 不把发票管理接入投资证据链。
- 不自动改写已有项目档案或历史研究产物。
- 不修改正在独立开发的 `jvc-research-report` worktree。
- 不为尚未观察到的规模问题引入数据库、消息队列或插件体系。

## 4. 总体架构

新增一个共享、不可直接调用的 `jvc-research-core`：

```text
用户调用 /jvc-*
  → skill 读取自己的研究配置
  → researchctl.py 初始化或恢复证据账本
  → 代理使用当前平台已有的搜索、浏览器和本地文件工具
  → researchctl.py 校验并追加证据记录
  → 代理生成原有业务产物
  → researchctl.py 对账本和最终产物执行终审
  → 输出 audit.json、audit.md 和研究状态
```

组件边界：

### 4.1 `jvc-research-core`

负责：

- 证据账本的数据契约；
- 证据记录的校验和原子追加；
- 记录引用、版本和内容指纹校验；
- 通用证据规则；
- skill 配置加载；
- `ready`、`partial`、`blocked` 判定；
- 例外许可记录；
- 审查结果生成。

不负责：

- 联网检索；
- 事实判断和投资判断；
- 报告写作；
- 工作簿、访谈纪要或可视化生成。

建议目录：

```text
skills/jvc-research-core/
├── SKILL.md
├── profiles/
│   └── jvc-*.json
└── scripts/
    ├── researchctl.py
    └── check_package.py
```

`SKILL.md` 标记为不可直接调用。`researchctl.py` 只使用 Python 标准库。
实现时优先使用项目约定的 `/yao-meta-skill` 创建和审查该新 skill，再删除不属于本设计的脚手架。

### 4.2 各业务 skill

各业务 skill 继续负责自己的用户结果和专业判断，只增加：

- 一个很小的研究配置；
- 初始化和终审命令；
- 研究状态对应的输出与停止规则；
- 对共享证据账本的读写约定。

通用研究方法只在内核维护，不复制到每个 `SKILL.md`。

## 5. 信息搜集底层范式

固定逻辑为：

```text
决策问题
  → 可证伪假设
  → 信息需求
  → 来源矩阵
  → 检索记录
  → 最小证据包
  → 主张—证据绑定
  → 反向检索
  → 冲突审查
  → 停止判断
```

规则：

1. 每次检索必须服务于一个明确问题，不先堆资料再寻找观点。
2. 研究开始时明确对象、边界、地域、时间、要支持的决策和不回答的问题。
3. 高优先级问题必须有可证伪假设、反证条件和证据完成标准。
4. 无结果检索也进入账本；“未找到”不得改写为“不存在”。
5. 普通网页只保存主张相关的最小原文摘录、元数据和内容指纹。
6. 官方文件和用户已有材料可以保存本地副本。
7. 决策关键的数字、政策、技术成熟度、客户采用和商业化主张，默认需要两类相互独立的来源。
8. 转载、聚合和引用同一原始出处的报道只算一个来源。
9. 公司自述可以作为“公司主张”记录，但不能自动升级为第三方事实。
10. 来源冲突先检查定义、地域、时间、样本、统计口径和立场，再并列口径或收窄结论。
11. 更正通过新增记录并指向被替代记录完成，不静默改写历史。
12. 高优先级问题已被支持、反证或明确标记为不可补齐，且连续两轮检索不再改变核心判断时停止。

## 6. 唯一事实源

每次研究目录只保留一个规范账本：

```text
<run-dir>/
├── evidence_registry.jsonl
├── audit.json
└── audit.md
```

业务报告、工作簿和纪要仍按原 skill 约定保存。`audit.json` 和 `audit.md` 是可重新生成的派生产物，不是证据事实源。

代理不得直接编辑 `evidence_registry.jsonl`。所有新增记录、更正和例外许可必须通过 `researchctl.py` 写入；内核在写入前完成格式、稳定标识符和引用校验。

所有账本记录包含：

- `schema_version`：记录格式版本；
- `record_id`：稳定标识符；
- `record_type`：记录类型；
- `created_at`：创建时间；
- `actor`：用户或代理角色；
- `created_by_skill`：产生本记录的业务 skill；
- `supersedes`：可选，被本记录替代的旧记录。

内核写入时另行补充单调递增序号、上一条记录指纹和本条记录指纹，形成可校验的追加链。调用方不得自行填写这些字段。终审会重算整条链，因此直接修改、删除、插入或重排历史记录都会使账本失效。

`init`、`record` 和审计汇总写入期间持有同一个独占单写者锁；锁已存在时失败关闭，避免两个代理并发追加或更新审计索引时后写覆盖先写。异常退出留下的锁只能在确认记录进程已不存在后人工移除。

Identifier（ID，标识符）用于稳定引用一条记录。实现时为不同记录类型使用可读前缀，避免依赖行号。

### 6.1 `scope`

字段至少包含：

- 初始创建账本的 skill；
- 研究对象；
- 要支持的决策；
- 纳入和排除边界；
- 地域和时间范围；
- 用户明确给出的假设。

### 6.2 `question`

字段至少包含：

- 问题文本；
- 优先级；
- 当前假设；
- 反证条件；
- 需要的证据；
- 当前状态。

### 6.3 `query`

字段至少包含：

- 关联问题；
- 实际检索式；
- 使用的工具类型；
- 目标来源类型；
- 执行时间；
- 检索轮次；
- 本轮是否改变核心判断；
- 结果数量；
- 结果摘要或无结果原因。

### 6.4 `source`

字段至少包含：

- 标题、发布主体和作者；
- 发布日期和访问时间；
- 来源类型；
- 链接或本地路径；
- 与主张直接相关的原文摘录；
- 定义、地域、样本和统计口径；
- 来源立场；
- 内容指纹；
- 独立来源分组。

内核可以确定性检查同一发布主体、相同链接、相同原始出处和显然相同的独立来源分组。语义上的真实独立性仍由代理记录并接受终审。

内容指纹由内核基于标题、发布主体、作者、发布日期、来源类型、位置、摘录、定义、地域、样本和统计口径组成的规范证据包计算；调用方给出不一致指纹时拒绝写入。

### 6.5 `claim`

字段至少包含：

- 主张文本；
- 类型：第三方事实、公司自述、用户观察、模型估算、代理推断或未知；
- 重要性；
- 支持证据；
- 反向证据；
- 上游主张标识符；
- 适用边界；
- 置信度；
- 推断过程；
- 当前状态。

### 6.6 `waiver`

字段至少包含：

- 被覆盖的规则；
- 原因；
- 影响范围；
- 批准者；
- 批准时间；
- 剩余风险。

格式损坏、断裂引用、内容指纹不一致和安全边界不得被例外许可覆盖。例外只适用于用户明确接受的业务证据缺口。

## 7. 固定命令

### 7.1 初始化或恢复

```bash
python3 "<core>/scripts/researchctl.py" init \
  --skill jvc-track-research \
  --run-dir "<研究目录>" \
  --scope-file "<研究范围.json>"
```

`--scope-file` 是一条完整、可校验的 `scope` 记录。默认拒绝覆盖已存在的规范账本。后续 skill 复用同一账本时，必须以自己的 skill 名称显式执行 `init --resume`；恢复时不得同时提供新的 `--scope-file`，范围变化通过更正记录完成。

### 7.2 登记证据

```bash
python3 "<core>/scripts/researchctl.py" record \
  --run-dir "<研究目录>" \
  --input "<待登记记录.jsonl>"
```

`--input` 可以包含一条或多条记录。内核先校验全部记录及其相互引用，全部通过后再原子追加；任何一条失败都不改变规范账本。更正记录通过 `supersedes` 指向旧记录。

### 7.3 终审

```bash
python3 "<core>/scripts/researchctl.py" audit \
  --run-dir "<研究目录>" \
  --skill jvc-track-research \
  --artifact "<最终产物>"
```

`--artifact` 可以重复传入，以覆盖工作簿、纪要或多文件知识树。终审读取账本、指定 skill 的 profile 和全部最终产物，生成 `audit.json` 与 `audit.md`。

每条审查记录保存 skill 名称、审查时的账本序号、截至该序号的账本指纹、全部最终产物指纹、profile 指纹、内核运行时指纹、上游审查绑定和研究状态。后续通过内核合法追加的新记录不会使前序审查失效；修改、删除或重排已审序号以内的记录，修改对应最终产物、profile 或内核，或者使绑定的上游审查失效，都会使相关审查失效。`audit.json` 保留各 skill 的有效审查记录，`audit.md` 汇总当前研究链状态。

### 7.4 例外许可

```bash
python3 "<core>/scripts/researchctl.py" waive \
  --run-dir "<研究目录>" \
  --rule "<规则名称>" \
  --reason "<原因>" \
  --scope "<影响范围>" \
  --approved-by "<批准者>"
```

例外许可必须精确匹配同一 skill 最新有效审查中的一个业务证据 blocker，只把相关 `blocked` 降为 `partial`，不能得到 `ready`。通用 `record` 命令不得创建 waiver。

## 8. 终审规则和状态

终审至少检查：

- 账本格式、稳定标识符和记录引用有效；
- 研究范围和决策问题明确；
- 所有高优先级问题都有支持、反证或证据缺口状态；
- 所有重要主张绑定证据或标记为未核实；
- 决策关键主张满足独立来源要求；
- 已执行反向证据检索；
- 来源日期、口径、立场和适用范围完整；
- 冲突证据已解释或导致结论收窄；
- 可解析最终产物中的来源引用与证据账本一致；
- 各 profile 声明的产物验证命令已经通过；
- 例外许可包含原因、范围、批准者和剩余风险；
- 终审记录中的账本前缀指纹及最终产物指纹仍然有效。

结果：

| 状态 | 命令退出状态 | 含义 |
| --- | ---: | --- |
| `ready` | `0` | 可以宣称研究完成；非关键警告可以保留 |
| `partial` | `10` | 可以交付，但标题和结论必须明确研究不完整 |
| `blocked` | `20` | 只能交付证据缺口和下一步计划，不能形成受影响的判断 |
| 工具错误 | `1` | 内核、配置或账本损坏，修复后必须重跑 |

首次计算为 `partial` 但最终产物尚未包含 `研究状态：partial` 时，终审先返回 `blocked`；代理补齐标题和结论标记后必须重跑，当前产物得到退出状态 `10` 才能交付。

## 9. 各 skill 接入

| Skill 层 | 接入方式 | 强制检查 |
| --- | --- | --- |
| `jvc-meeting-notes`、`jvc-talk-notes` | 把逐字稿、用户随笔和纪要登记为本地来源；区分受访者自述、用户观察和原始文本 | 来源路径、发言主体、日期和事实类型完整 |
| `jvc-prescreen` | 从本地材料建立或复用账本，不默认联网扩展 | 每条关键判断可追溯，未知不得补写 |
| `jvc-bull-case`、`jvc-bear-case` | 在原账本上新增正向或反向分析主张，不复制来源 | 支持证据、反向证据、反证条件完整 |
| `jvc-track-research`、`jvc-comps-dd`、`jvc-market-sizing` | 使用完整研究链 | 独立来源、冲突、口径、时效和覆盖度 |
| `jvc-knowledge-tree-builder` | 将现有 `source_manifest.json` 映射进统一账本，保留稳定来源编号 | 本地文件与知识树节点、证据索引一致 |
| `jvc-roi-modeler` | 登记条款、预测和模型假设的来源；现有工作簿脚本继续负责产物结构 | 已知条款与用户假设分开，公式输入可追溯 |
| `jvc-ic-memo` | 只消费已经终审的证据和分析主张；新增事实必须先入账 | 每个决策关键结论可追溯，引用与账本一致 |
| `jvc-invoice-manager` | 不接入 | 保持运营工具边界 |
| 在途的 `jvc-research-report` | 本次只预留兼容接口，不修改其 worktree | 独立完成后再添加配置 |

Return on Investment（ROI，投资回报率）用于衡量投入资本产生的回报。Investment Committee Memo（IC Memo，投资决策委员会备忘录）是提交基金内部投决审议的研究文件。

每个 profile 只声明：

- 需要哪些账本记录；
- 哪些主张属于决策关键项；
- 独立来源最低要求；
- 特定时效或口径规则；
- 最终产物及现有验证命令。

profile 可以增加要求，不得关闭通用的数据完整性和安全规则。

Markdown 来源引用由内核直接检查。工作簿、访谈纪要和多文件知识树复用仓库已有的产物验证脚本；profile 只能引用随包发布且经过治理清单批准的固定命令，不接受研究数据提供的任意命令字符串。

## 10. `SKILL.md` 编写边界

每个被修改的 `SKILL.md` 只保留会影响行为的内容：

- 用户可见目标；
- 可验证成功标准；
- 业务、证据和权限约束；
- 可用工具及必跑命令；
- 必须保留的输出；
- 继续、重试、降级、询问和结束条件。

代理自行选择高效的检索词、工具顺序和表达路径。通用来源分级、主张绑定、冲突处理和状态逻辑由内核及 profile 承担，不在 prompt 中重复。

## 11. 安装与运行边界

- 现有 `setup` 同时安装 `jvc-research-core`，但不把它列入用户命令清单。
- 各 skill 根据自身 `SKILL.md` 的实际路径解析同级内核，不依赖当前工作目录或全局命令搜索路径。
- 所有命令路径加引号，支持空格和中文目录。
- 内核只使用 Python 标准库，不增加运行依赖。
- 内核调用产物验证器时使用参数数组，不经过 shell 解释，不执行远程代码。
- `init` 采用临时文件完成后替换，避免中断造成半截账本。
- `record` 先校验整个输入批次，再原子追加，禁止部分成功。
- `audit` 不反向修改规范账本。
- 找不到内核、配置版本不兼容、账本损坏或命令异常时，禁止退回纯 prompt 模式。
- 搜索结果为空、残缺或异常狭窄时，尝试一至两个有意义的检索变体；仍无结果则登记证据缺口。
- 用户中断后可以从现有账本恢复，已经登记的证据不需要重新搜索。

## 12. 兼容与迁移

- 原有 skill 名称和用户入口不变。
- 原有 Markdown、工作簿和访谈纪要输出不改名。
- 已有项目不会被批量迁移。
- 对没有账本的历史项目，用户可以新建研究目录并把历史产物登记为本地来源；默认不自动反向抽取历史主张。
- package 版本升级为 `2.0.0`。被修改 skill 的版本字段随发布同步更新。
- profile 和账本都包含格式版本；版本不兼容时明确阻断，不做静默猜测。

## 13. 错误处理

- 输入不合法：指出记录和字段，退出状态为 `1`。
- 直接编辑导致账本内容不符合追加规则：阻断终审，必须从有效记录恢复。
- 引用断裂或重复稳定标识符：阻断终审。
- 决策关键证据不足：`partial` 或 `blocked`，取决于是否仍能形成收窄后的可靠结论。
- 来源冲突未处理：相关主张为 `blocked`。
- 仅有公司自述：保留为公司主张；若被写成第三方事实则阻断。
- 例外许可不完整：视为无效，不改变状态。
- 已审账本前缀或对应最终产物改变：相关旧审查失效，必须重跑；仅在末尾合法追加不会破坏前序审查。
- 写入中断：保留原文件，临时文件可以安全清理。

## 14. 验证设计

### 14.1 内核自检

`skills/jvc-research-core/scripts/check_package.py` 至少覆盖：

- 初始化和恢复；
- 单条与批量记录的原子追加；
- 并发写锁和失败关闭；
- 非法记录和断裂引用；
- 三种研究状态；
- 例外许可；
- 过期内容指纹；
- 中断写入不破坏原账本。

### 14.2 全 skill 契约检查

扩展现有 `scripts/check-skill-evals.py`：

- 每个接入 skill 至少有一个完整 profile 样例；
- `SKILL.md` 包含必跑命令和停止规则；
- 关键主张类别、来源要求和最终产物与 profile 一致；
- 未接入的 skill 有明确边界。

不新建重复的 suite 级评测框架。

### 14.3 真实端到端案例

至少覆盖：

1. 本地访谈材料到初筛；
2. 包含冲突来源的公开赛道研究；
3. 明确区分外部事实和模型假设的市场建模；
4. 多份已审材料到最终备忘录；
5. 故意缺失关键证据且必须得到 `partial` 或 `blocked` 的负向案例。

每个案例保存规范账本、最终产物和终审结果。

### 14.4 发布前盲评

选择两个最高风险的公开研究案例，对比 1.0 与 2.0 输出，不显示版本。人工按以下维度审查：

- 事实准确性；
- 主张可追溯性；
- 来源独立性；
- 冲突和反证处理；
- 结论校准；
- 对下一步尽调的帮助。

没有实际执行并保存的模型与工具运行结果时，不得声称已经证明真实输出质量提升。

## 16. 已确认的简化

- 使用共享内核，不做统一工作流引擎。
- 使用 JSONL，不引入 SQLite。
- 使用平台已有搜索工具，不绑定外部搜索服务。
- 保存最小证据包，不完整镜像普通网页。
- 使用三级状态，不输出伪精确的研究质量百分数。
- 允许有记录的业务例外，但不允许绕过数据完整性和安全规则。
- `jvc-research-report` 延后独立接入。
