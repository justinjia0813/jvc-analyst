# JVC IC Memo 预审版与终版设计

日期：2026-08-08
状态：设计已确认，待用户审核规格文件

## 1. 背景

`/jvc-ic-memo` 当前只定义一种 Markdown 产物：正文包含来源标注、证据状态、缺口和质量报告。该形态适合投资经理内部审查，但不适合直接交给 IC（Investment Committee，投资决策委员会，负责审议投资项目）阅读。

本次改动把 IC Memo 分成两个顺序生成的 Markdown 产物：

1. 预审版面向投资经理，完整暴露证据与质量问题。
2. 终版面向 IC 委员，只保留经过批准的信息与判断，以清晰传达为目标。

Quarto 负责后续 HTML（HyperText Markup Language，超文本标记语言，用于浏览器呈现）输出和视觉样式；本 skill 不生成 Word、PDF 或演示文稿，也不内置 Quarto 样式。

## 2. 目标

- 保留现有证据审计强度，但不把内部审查痕迹带入 IC 终版。
- 强制执行“先预审、后终版”的人工闸门。
- 两份产物共享同一套十七章内容结构，避免维护两套模板。
- 终版不增加预审版没有的新事实、数字或判断。
- 终版保持标准 Markdown，便于 Quarto 统一渲染。

## 3. 非目标

- 不拆分新的 `/jvc-ic-memo-review` 或 `/jvc-ic-memo-final` skill。
- 不通过机械删除标签直接生成终版。
- 不在本次改动中设计 Quarto 主题、网页样式或导出流程。
- 不新增数据库、工作流框架或第二套证据内核。
- 不让代理替用户作出投资、否决或等待的终局决定。

## 4. 产物合同

### 4.1 预审版

文件名：`06-ic-memo-review.md`

预审版是证据内核审查的正式产物，必须包含：

- 十七章正文中实际可用的内容；
- 来源编号、来源类型和必要的来源索引；
- `[未核实]`、`[需要用户提供]`、冲突数据和证据状态；
- 章节级质量门控结果；
- 数据一致性检查；
- 待用户裁定事项；
- 未覆盖章节和关键证据缺口；
- `ready`、`partial` 或 `blocked` 研究状态。

预审版默认先生成。没有预审版及其最新审查结果时，不得进入终版阶段。

### 4.2 终版

文件名：`06-ic-memo.md`

终版是交给 IC 委员阅读并供 Quarto 渲染的正式内容文件，必须满足：

- 不出现来源编号、来源列表、网页链接或页码引用；
- 不出现证据等级、证据状态、研究状态、素材覆盖率或质量报告；
- 不出现 `[未核实]`、`[需要用户提供]`、`待确认`、占位符或内部操作说明；
- 不出现“辅助生成初稿”等面向内部生产过程的提示；
- 信息充分时使用确定性陈述；
- 信息不能完全确定但经用户批准保留时，使用“可能”“预计”“约”“区间为”“在某情景下”等正文表达；
- 不新增获批预审版中不存在的事实、数字或判断；
- 没有有效内容的章节直接省略，不保留空章节；
- 保持标准 Markdown 标题、段落、列表和表格，不嵌入表现层样式。

## 5. 单 skill 双阶段工作流

`/jvc-ic-memo` 保持一个用户入口，内部包含两个明确阶段。

### 阶段一：生成预审版

1. 扫描项目素材和前序 JVC skill 产物。
2. 按现有十七章模板生成 `06-ic-memo-review.md`。
3. 登记来源与主张，运行 `jvc-research-core` 审查。
4. 输出预审结果、冲突、缺口和需要用户裁定的事项。
5. 停止，等待用户明确审批。

### 人工闸门

只有用户明确表达“预审通过”或等价授权后，才能进入阶段二。审批前至少确认：

- 数字冲突已经裁定；
- 保留的不确定信息已经确定合适的概率、区间或情景表达；
- 关键证据缺口已经决定转化为业务风险或从终版删除；
- 用户明确授权生成终版。

`blocked` 预审版不得生成终版。`partial` 预审版只有在用户明确接受剩余不确定性后才可继续。

### 阶段二：生成终版

1. 读取最新预审版、最新审查结果和本轮用户裁定。
2. 依据第 6 节的规则重新组织正文，不做机械标签删除。
3. 生成终版候选文件。
4. 运行终版校验器。
5. 校验通过后发布或更新 `06-ic-memo.md`。

未经新一轮审批，不得用新预审版覆盖已有终版。新资料使预审内容变化时，旧终版视为待更新，但保持原文件不变，直到新终版通过校验。

## 6. 内容转换规则

| 预审版内容 | 终版处理 |
| --- | --- |
| 已确认的信息 | 改为直接、确定性陈述 |
| 合理但无法完全确定的判断 | 使用概率、区间、预计或情景表达 |
| 来源编号、来源名称、链接、页码 | 删除 |
| 证据等级、证据状态、研究状态 | 不显示；按用户裁定改写或删除相关内容 |
| 数字冲突 | 不自动选择；没有用户裁定则停止终版生成 |
| 缺失信息、待补材料 | 删除，不保留占位符 |
| 对投资判断有实质影响的证据缺口 | 经用户批准后转化为业务风险表达，或从终版删除 |
| 质量报告、审查清单、待办事项 | 只保留在预审版 |
| 风险与反方信息 | 保留实质内容，改写为面向 IC 的完整风险论述 |
| 新事实、新数字、新判断 | 禁止加入 |

证据缺口转为业务风险时，不描述取证过程。例如，预审版中的“缺少连续订单证据”可以在终版表达为“未来收入仍可能受到订单转化速度影响”，但不能写成已经发生的确定损失。

## 7. 审查与校验

### 7.1 预审版审查

预审版继续使用现有 `jvc-research-core`：

- 登记 scope、question、source 和 claim；
- 要求数字与重要主张可追溯；
- 运行 `jvc-ic-memo` profile；
- 根据审查结果产生 `ready`、`partial` 或 `blocked` 状态。

证据内核只把预审版作为正式审查产物。终版不因隐藏引用而降低预审阶段的证据要求。

### 7.2 终版校验

新增一个使用 Python 标准库实现的小型只读校验器。它不负责生成或机械清洗正文，只检查：

- 终版不存在来源编号、来源索引、网页链接和页码引用；
- 终版不存在内部标签、研究状态、质量报告、待确认项和占位符；
- 终版不存在空章节；
- 终版标题、列表和表格保持有效 Markdown 结构；
- 终版中的数字经规范化后都能在获批预审版中找到。

校验器不能证明语义完全一致。语义边界由预审证据审查、用户审批和终版生成规则共同保证。

## 8. 失败处理

- 找不到预审版或最新审查结果：停止，不生成终版。
- 预审状态为 `blocked`：停止，只报告阻断项。
- 预审状态为 `partial` 且用户未明确接受：停止，等待决定。
- 存在未裁定的数字冲突：停止，逐项请求用户裁定。
- 终版出现内部标签、来源或新数字：校验失败，不发布候选文件。
- 已有终版存在而新候选失败：保留已有终版，不覆盖。
- 证据内核、模板或校验器不可用：失败关闭，不退回无审查的纯 prompt 流程。

## 9. 现有一致性问题

实现本设计时必须同时修复两个直接影响正确性的问题：

1. `skills/jvc-ic-memo/SKILL.md` 要求读取 `references/ic-memo-template.md`，但当前模板实际位于仓库根目录 `templates/ic-memo-template.md`。安装后的 skill 必须包含自己的模板资源，并且只保留一个权威版本。
2. 当前模板包含“建议投/不投/有条件投”，与 skill 的“不替用户作终局判断”硬约束冲突。模板应改为呈现交易条件、收益情景和待 IC 决定事项，不替用户生成终局决定。

## 10. 回归检查

最小回归检查覆盖：

1. 预审版保留来源、证据状态、冲突和质量报告。
2. 未经明确批准不得生成终版。
3. `blocked` 预审版不得生成终版。
4. `partial` 预审版必须有用户接受记录才能继续。
5. 终版出现来源编号、链接或内部标签时校验失败。
6. 终版出现预审版没有的数字时校验失败。
7. 终版没有空章节和占位符。
8. 校验失败时不覆盖已有终版。

## 11. 成功标准

- `/jvc-ic-memo` 默认只生成并审查 `06-ic-memo-review.md`。
- 用户明确批准前，流程在人工闸门停止。
- 批准后生成的 `06-ic-memo.md` 不包含任何引用、证据状态、缺口标签或质量报告。
- 终版的不确定内容使用自然的概率、区间或情景表达。
- 终版没有预审版之外的新数字。
- 两份 Markdown 可以由 Quarto 读取，且不依赖 skill 内的视觉样式。
- 相关静态检查、证据链案例和终版校验回归检查全部通过。
