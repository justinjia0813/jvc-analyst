# 尽调报告消化

把一份几十上百页的第三方尽调报告，压成一份 3–5 页、能直接用于投决讨论和条款谈判的摘要。交付 `dd-digest-{报告类型}.md`，例如 `dd-digest-财务.md`。

## 适用级别

最低适用级别：**L2+**（拿到第三方尽调报告时通常已在尽调阶段；不要求先建任何项目档案，直接调用即执行）。

## 输入

- 尽调报告：财务、法律、审计、业务/技术、环境等，PDF 或 Word。
- 可选：BP、管理层访谈纪要、初筛或商业经济分析，用来对照口径。
- 可选：同一报告的多个版本（初稿、draft、终稿）。
- 可选：本轮条款清单（TS，Term Sheet）或投资协议草稿。

## 执行

1. 读 [各类报告的关注清单](references/checklists.md)。
2. 把报告转成可读文本（优先用本机文档转换工具，复杂 PDF 保留表格）。报告保持本地，不上传任何外部工具。
3. 通读全文，按关注清单抽取发现。每条发现标报告页码 `[财务DD p.N]`，方便回查。
4. 有 BP 或纪要时，逐项对照：收入、利润、客户、订单、人数、股权、诉讼等说法和报告是否一致。
5. 有多个版本时，列出版本之间实质性的增删改（数字变了、风险措辞变软、某项发现被删）。
6. 判断每条红旗对交易的影响：估值调整、先决条件、陈述与保证、特别赔偿、交割后整改、还是可以接受。

## 输出结构

```
# {公司}：{报告类型}尽调摘要｜报告出具方｜报告日期｜版本

## 一句话结论（3–5 句：这份报告最重要的发现是什么，对交易意味着什么）

## 红旗（按严重程度排序）
| # | 发现 | 严重程度 高/中/低 | 对交易的影响 | 建议的条款处理 | 出处 |

## 与 BP / 管理层口径不一致的地方
| 事项 | BP 或管理层说法 | 报告说法 | 差异可能的原因 |

## 关键数字（报告口径）
（收入、毛利、净利、经营现金流、应收、存货、负债、股权结构等，附页码）

## 版本差异（有多个版本时）

## 要追问的问题（给管理层或尽调机构）

## 报告本身的局限
（报告的范围限制、依赖管理层提供未核实的部分、明确未覆盖的事项；一段话即可）
```

## 文件位置

用户指定路径优先；否则写进材料所在的项目或赛道文件夹根目录（不放进原始材料子目录）；都没有时问一次放哪。中间文件（JSON、转出的文本、计算脚本、证据台账）放在同目录的 `_work/`。同名文件已存在时不覆盖，加日期后缀。

## 反合理化约束

- 报告写“管理层提供、未经核实”的内容，照样是管理层口径，不因写进尽调报告就变成第三方事实。
- 尽调机构用词偏软时（“存在一定不规范”），按实际事实定严重程度，不照抄措辞。
- 不遗漏报告里的范围限制和免责条款：它们说明哪些事没查。
- “建议的条款处理”是给用户的谈判选项，不是投/不投的结论。
- 证据内核默认不启用。

## 完成

合伙人读完一句话结论和红旗表，就知道这份尽调有没有发现影响交易的问题、该在条款里怎么处理、还有什么要追问。
