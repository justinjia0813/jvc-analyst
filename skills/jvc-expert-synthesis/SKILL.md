# 多方访谈交叉比对

回答“几场访谈加起来，哪些事大家都这么说、哪些事说法打架、该信谁、下一轮该问什么”。默认交付 `expert-synthesis-{主题}.md`。

## 适用级别

最低适用级别：**L1+**（至少两场关于同一主题或同一项目的访谈纪要或逐字稿）。

## 输入

- 两份以上访谈纪要或逐字稿（必需）。单场原始逐字稿先用 `jvc-meeting-notes` 整理更稳。
- 每位受访者的身份（必需，缺了就问）：职位、所在公司类型、与项目的关系（客户、竞品、供应商、前员工、独立专家、投资人）。
- 这次最想搞清楚的问题（可选）；没说就从纪要里找最影响投资判断的 3–6 个议题。

## 执行

1. 读 [比对方法](references/method.md)。原始纪要只读。
2. **建议题。** 按投资判断需要的议题归类（市场需求、技术路线、价格与成本、竞争格局、客户采购决策、监管等），不按访谈顺序。
3. **逐题对齐。** 每个议题下列出每位受访者的说法，关键处用原话，标注 `[受访者编号, 纪要位置]`。没谈到的写“未涉及”，不推测其立场。
4. **分三类：** 共识（多人独立说出、且来自不同立场）；分歧（说法冲突）；孤证（只有一人提到但影响大）。
5. **判可信度。** 对每个分歧，写各方可能的立场偏差（利益关系、信息位置、时效）和更可信的一方及理由；判断不了就写“无法判断”，并写需要什么证据。
6. **口径对齐。** 数字冲突先查口径（时间、范围、单位、含税与否、是否包含某类产品），能解释的写明，不能解释的保留两种说法。
7. **出下一轮问题。** 针对分歧和孤证，写最能分辨谁对的问题和最适合问的对象。要进会议室时交给 `jvc-interview-prep`。

## 输出结构

```

## 结论（3–5 句：哪些事可以当作较确定的判断、最大的分歧是什么、该信谁、最可能错在哪）

## 受访者一览
| 编号 | 身份 | 与项目关系 | 可能的立场偏差 | 访谈日期 |

```

## 文件位置

用户指定路径优先；否则写进材料所在的项目或赛道文件夹根目录（不放进原始材料子目录）；都没有时问一次放哪。中间文件（JSON、转出的文本、计算脚本、证据台账）放在同目录的 `_work/`。同名文件已存在时不覆盖，加日期后缀。

## 反合理化约束

- 共识不等于事实：同一立场的多人说法相同（例如三位都是同一家公司的客户）只算一条证据。
- 不按人数投票决定谁对；看信息位置和利益关系。
- 不把受访者没说的话归给他；原话改写时不改变含义和条件。
- 不把自己的判断写进受访者的说法里；判断只出现在“更可信”和结论里。
- 不写投/不投的结论。
- 证据内核默认不启用；用户要求 `--rigor` 时按 [调用合同](../jvc-research-core/references/caller-contract.md) 以 `jvc-expert-synthesis` 身份审查。

## 完成

用户读完结论，就知道几场访谈合起来真正确认了什么、哪个分歧最影响判断、下一通电话该打给谁问什么。
