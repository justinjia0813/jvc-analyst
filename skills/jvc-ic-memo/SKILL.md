# /jvc-ic-memo — 投决备忘录（预审与终版双阶段）

汇总所有前序 JVC skill 产出和原始素材，按标准化模板依次生成保留证据的预审版与经人工批准的干净终版。默认只生成预审版并停止。

这是本工具箱里**唯一默认使用严格证据审查的 skill**：上会材料的错误代价最高，所以证据内核在这里以 `--mode gate` 运行，`blocked` 时不形成受影响的判断。其他 skill 的“判断在前、证据在附录”规则不适用于预审版；预审版必须完整暴露来源、冲突和缺口。

运行前**必须**读取本 skill 目录下的 `references/ic-memo-template.md`——它是每个章节的结构定义、内容标准、数据要求和质量门控的唯一权威来源。本文件定义生产流程和 skill 映射；模板定义内容规范。两者配合使用。

## 适用级别

最低适用级别：**L3**（重仓、领投或投决会前研究）。

- 开始前读取项目已有的初筛、纪要、商业经济、赛道研究、工作簿、投资论点和证据索引。
- 项目低于 L3 时，先列出尚缺的 IC 前工件和关键证据，由用户确认是否只生成明确标注不完整的预审版。
- Memo 只整理证据、分歧和待决事项；`decision-journal.md` 由人在做出决定时立案，本 Skill 不代写终局判断。

读取论点时接受 `04-thesis-test.md`，以及历史 `04-bull-case.md`、`04-bear-case.md`（旧项目也可能使用 `bull-case.md`、`bear-case.md`）。按证据台账路径、原调用身份与解析后的主张编号识别同一主张；跨台账的裸编号不能用于去重。保留冲突，不将新旧文件重复计为独立证据。

访谈事实读取纪要的工作版（含待验证点）和原始逐字稿；历史 `claim-audit.md` 继续接受。纪要记录的是受访者说法，不能把其中公司自述当已核验事实；同一次访谈的交付版、工作版和主张表是同源表达，不重复计为独立证据。

行业内容接受 `landscape.md`、`industry-mechanics.md`；竞争内容接受 `competitive-positioning.md` 和可比公司工作簿。回报内容以投资回报工作簿为主，历史 `return-underwriting.md`、`decision-memo.md` 可作参考但不替代本身份的预审审查。缺失章节仍列缺口。

## 轻量模式：判断状态综合

用户只想在上会前把重大判断的状态理清、还不需要十七章时，交付 `decision-memo.md`：

- 每个重大判断一行：问题、状态、支持证据、最强反证、成立条件、需要人裁定的分歧。
- 状态只有四种：**已成立**（当前证据下成立）、**未成立**（有反证）、**条件成立**（写明还差什么条件）、**待裁定**（需要人拍板的分歧）。缺证据写“待验证”，不判为未成立。
- 不跑十七章模板，不运行 `validate_final.py`，不替代预审版或用户批准。默认不启用证据内核。

## 文件位置

用户指定路径优先；否则写进材料所在的项目或赛道文件夹根目录（不放进原始材料子目录）；都没有时问一次放哪。中间文件（JSON、转出的文本、计算脚本、证据台账）放在同目录的 `_work/`。同名文件已存在时不覆盖，加日期后缀。

## 反合理化约束

- "前序材料已经很多，可以直接合成" → 数量不等于覆盖；先核对关键假设、反证、来源与未解决冲突。
- "为了让 memo 完整可以补齐空白" → 不编造；缺口留在待决事项并标明责任人或下一步。
- "风险会削弱投资逻辑，可以压缩" → 风险篇幅不得短于投资亮点，反面证据不得移到附件隐藏。
- "IC memo 需要明确推荐" → AI 不写建议投资/不建议投资，只呈现条件、证据和未决问题。
- "终版只是把预审版引用删掉" → **不做机械标签删除**；按用户裁定重新组织，不能把未核实内容伪装成确定事实。
- "research-core 显示 ready，可以自动出终版" → ready 不是用户批准；只有用户明确说出“预审通过”或给予等价授权后才能生成终版。
- "终版顺手补充一点信息更完整" → 终版不得增加获批预审版没有的事实、数字或判断；新增内容必须回到预审流程。

## 六阶段生产流程

### Phase 1: 素材准备与清点

读取项目目录下的所有可用素材，按下方「JVC Skill 产出到模板章节映射表」逐章标记：✅ 已有 / ⚠️ 部分可用 / ❌ 缺失。

向用户输出素材清点表，格式：

```
素材清点结果（[项目名]）

| 模板章节 | 需要的 JVC skill 产出 | 状态 | 备注 |
|---------|---------------------|------|------|
| 1. 执行摘要 | 初筛 / 投资回报工作簿 | ✅/⚠️/❌ | ... |
| ... | ... | ... | ... |

❌ 缺失项（共 x 项）：
- [列出缺失项及其对 memo 质量的影响]
- [建议用户先运行哪些 skill]

是否继续？缺失章节将标注「此部分缺少输入素材」。
```

用户确认继续时，只生成明确标注不完整的预审版。素材缺失不等于可绕过 research-core audit 的 `blocked` / `partial` / `ready` 合同和人工批准；绝不能因此自动进入终版。

### Phase 2: 骨架搭建

1. 读取 `references/ic-memo-template.md` 获取完整结构
2. 填写执行摘要的交易概要部分（先锚定核心数字）
3. 列出各章节的关键论点骨架（每章 3–5 个要点），向用户展示骨架供确认
4. 用户确认或调整骨架后进入 Phase 3

### Phase 3: 逐章填充

按依赖顺序分层填充，严格遵循模板中每章的结构规范和数据要求：

```
行业层（不依赖公司数据）：
  4. 行业概况 → 5. 市场规模 → 6. 产业链分析 → 7. 竞争格局

公司层（不依赖判断）：
  8. 公司概况 → 9. 产品矩阵 → 10. 核心团队 → 11. 核心壁垒 → 12. 主要客户

判断层（依赖行业层 + 公司层）：
  2. 投资亮点 → 3. 投资风险

估值层（依赖判断层 + 公司层）：
  14. 收入预测模型 → 15. 可比公司 → 16. 投资回报模型 → 13. Cap Table

汇总层：
  17. 交易-收益测算总结 → 1. 执行摘要（回写）
```

### Phase 4: 质量门控

完成全文后，执行三轮校验：

**第一轮：章节级质量门控**
逐章执行模板中定义的质量门控 checklist（每章末尾的 `[ ]` 项）。未通过的项标记为 `❌ 未通过: [原因]`，汇总后向用户报告。

**第二轮：数据一致性校验**
按模板附录「数据一致性校验清单」逐项核对：

| 数据点 | 涉及章节 | 校验方法 |
|--------|---------|---------|
| 收入数据 | 执行摘要 ↔ 收入预测模型 | 直接比对 |
| 净利润数据 | 执行摘要 ↔ 收入预测模型 ↔ 投资回报模型 | 直接比对 |
| 估值/融资金额 | 执行摘要 ↔ Cap Table ↔ 投资回报模型 ↔ 交易总结 | 直接比对 |
| 回报倍数 | 执行摘要 ↔ 投资回报模型 ↔ 交易总结 | 直接比对 |
| 市场规模 | 市场规模 ↔ 行业概况 | 交叉引用 |
| 竞品数据 | 竞争格局 ↔ 可比公司 | 数据源一致 |
| 客户数据 | 主要客户 ↔ 收入预测模型 | 逻辑一致 |
| 持股比例 | 核心团队 ↔ Cap Table | 直接比对 |
| 产品结构 | 产品矩阵 ↔ 收入预测模型 | 产品线对应 |

不一致的数据点在 memo 末尾「质量报告」中列出，标明来源冲突，请用户裁定。

**第三轮：全局硬约束检查**
- [ ] 风险章节（第 3 章）字数 ≥ 亮点章节（第 2 章）字数
- [ ] 风险条数 ≥ 亮点条数
- [ ] 至少有一条风险涉及估值/退出
- [ ] 每条风险有量化影响评估
- [ ] 所有数字可追溯到素材来源——无来源的标 `[未核实]` 或 `[需要用户提供]`
- [ ] 不出现没有证据的修饰词（"领先的"、"颠覆性的"、"赋能"、"护城河"等）
- [ ] 不出现 "建议投资" / "不建议投资" 等终局判断
- [ ] 口径说明完整（收入含税/不含税、人民币/美元）
- [ ] 缺失素材的章节有显式标注
- [ ] 术语首次出现附中文解释

### Phase 5: 预审版组装与审查

1. 修复 Phase 4 发现的问题；不能自行解决的数据冲突保留并请求用户裁定。
2. 按十七章顺序组装 `06-ic-memo-review.md`。正文主张保留 `[S编号]` 等引用，并显式保留证据状态、来源冲突、证据缺口和未覆盖章节。
3. 在预审版末尾附「质量报告」：通过/未通过的门控项、待用户裁定的数据冲突、证据缺口和未覆盖章节。
4. 只把 `06-ic-memo-review.md` 交给 research-core audit，并同时读取命令退出状态与 `audit.json`：
   - `blocked`：只报告阻断项与下一步，不生成终版。
   - `partial`：显式报告剩余不确定性；未经用户明确接受这些不确定性，不生成终版。
   - `ready`：仍停止并等待用户明确批准，不自动生成终版。

### Phase 6: 人工批准后生成终版

仅当用户明确说出“预审通过”或给予语义等价的授权后，才执行本阶段。

1. 读取最新的 `06-ic-memo-review.md`、对应 `audit.json` 和用户对冲突、缺口及不确定性的裁定。
2. 以下任一情况均停止：没有审查结果；audit 为 `blocked`；audit 为 `partial` 且用户未明确接受剩余不确定性；仍有未裁定的数字冲突。
3. 根据用户裁定重新组织正文，**不做机械标签删除**：
   - 已确认的信息用确定性陈述。
   - 不完全确定但获准保留的信息用“可能”“预计”“约”“区间”或“情景”等限定表达。
   - 删除来源、引用、页码引用、证据状态、研究状态、质量报告、缺口标签、占位符和内部操作说明；空章节省略。
   - 不增加获批预审版中没有的事实、数字或判断。
4. 先将候选终版写入与目标文件同目录的临时路径，运行：

   ```bash
   python3 "<skill-root>/scripts/validate_final.py" --review "<project>/06-ic-memo-review.md" --final "<temporary-final>"
   ```

5. validator 通过后才将候选文件发布为 `06-ic-memo.md`；失败时保留已有 `06-ic-memo.md` 不变，并报告失败原因。

## 十七章结构速览

每章的详细结构定义、模板代码块、质量门控清单见 `references/ic-memo-template.md`。以下仅列章节名称和定位：

| # | 章节 | 一句话定位 |
|---|------|----------|

| 6 | 产业链分析 | 回答「价值如何分配，标的卡在什么位置」 |
| 7 | 竞争格局 | 回答「标的在同行中排第几，靠什么赢」 |
| 8 | 公司概况 | 标的公司快照（简洁完整，不展开分析） |
| 9 | 产品矩阵 | 回答「靠什么挣钱，产品之间什么关系」 |
| 10 | 核心团队 | 回答「这帮人能不能把事做成」 |
| 11 | 核心壁垒 | 回答「别人为什么做不了同样的事」 |
| 12 | 主要客户 | 回答「谁在买单，付费意愿和能力如何」 |
| 13 | Cap Table | 回答「股权怎么分的，条款怎么保护我们」 |
| 14 | 收入预测模型 | 回答「未来 3–5 年能赚多少钱」——量 × 价，非拍增速 |
| 15 | 可比公司 | 回答「市场给类似公司什么估值」 |
| 16 | 投资回报模型 | 回答「我方投了能赚多少倍」——三种情景 + 稀释 |
| 17 | 交易-收益测算总结 | 全文最后的决策浓缩——一页纸让 IC 委员做判断 |

## 证据内核（必须）

从本 `SKILL.md` 的实际目录解析同级 `../jvc-research-core/scripts/researchctl.py`，并使用绝对路径执行；不要依赖当前工作目录。

执行前必须读取同级 `../jvc-research-core/references/evidence-contract.md` 和当前 profile `../jvc-research-core/profiles/jvc-ic-memo.json`。

1. 新研究先准备完整 `scope` JSON，再运行 `init --skill jvc-ic-memo --run-dir <研究目录> --scope-file <scope.json>`；初始 `scope` 只能通过 `init --scope-file` 创建。
2. 复用已有研究链时运行 `init --skill jvc-ic-memo --run-dir <研究目录> --resume`。后续 `scope` 更正必须通过 `record --run-dir <研究目录> --input <records.jsonl>` 登记，并用 `supersedes` 指向当前 effective scope；问题、检索、来源、主张和更正也只能通过该命令登记，不得直接编辑 `evidence_registry.jsonl`，generic `record` 不得创建 waiver。
3. 跨 skill 消费已有主张时，在新主张的 `derived_from_claim_ids` 中登记上游主张编号；缺失或失效的上游审计会阻断下游完成。
4. 预审版 `06-ic-memo-review.md` 中的本阶段支持与反证来源统一写为 `[S编号]`，并紧跟对应主张；预审版保留审查需要的引用、证据状态和冲突记录。
5. 完成 `06-ic-memo-review.md` 的生成与格式校验后，运行 `audit --run-dir <研究目录> --skill jvc-ic-memo --artifact <project>/06-ic-memo-review.md --mode gate`。本 skill 必须使用 `--mode gate`。每次 audit 必须同时读取命令退出状态和 `audit.json`。
6. 出现 `partial_label_missing`、`blocked_label_missing` 或 `artifact_status_mismatch` 时，按 finding 指明的状态修正当前可见标签与结论边界；已有标签就替换，无标签才补写，不能保留互相冲突的状态。XLSX 保持表头和列结构不变，状态写在 `sources` 数据行；Markdown 写在开头与结论，多文件同时核对各主件。修改后重新运行预审版格式校验，再重跑 audit；标签不能绕过业务证据阻断。重跑得到 `partial` / exit `10` 只能交付带剩余不确定性的预审版；`ready` / exit `0` 只能称为预审完成；其他 `blocked` / exit `20` 只能交付证据缺口和下一步，不能形成受影响的判断；exit `1` 必须修复后重跑。
7. 只有用户明确批准、且 blocker 与同 skill 最新有效 blocked audit 精确匹配时，才可运行 `waive --run-dir <研究目录> --skill jvc-ic-memo --rule <阻断规则> --reason <批准理由> --scope <批准范围> --approved-by <批准人> --residual-risk <剩余风险>`；不得自我批准，waiver 最多降级为 partial。

找不到内核、profile 不兼容、账本损坏或终审异常时，不得退回纯 prompt 模式。

本 skill 只消费有效审查记录；新增事实必须先登记，不能在 memo 中补造来源。

干净终版 `06-ic-memo.md` 是用户批准后的 presentation derivative（面向展示的派生版本），不交给要求 citation（引用）的 research-core profile；它只接受 `validate_final.py` 与本 skill 终版合同的校验。

## 执行步骤

### Step 1: 读取模板

读取 `references/ic-memo-template.md`，加载所有章节的结构定义和质量门控清单。

### Step 2: 素材准备（Phase 1）

1. 扫描项目目录，识别已有的 JVC skill 产出（按映射表匹配）
2. 历史项目若有 `STATE.md`、`DATA_LAYER.md`、`INVEST_MEMO.md`、`INSIGHT_LAYER.md`（旧编排器产物），作为素材读取
3. 输出素材清点表，等待用户确认

### Step 3: 骨架搭建（Phase 2）

1. 锚定交易核心参数（估值、金额、轮次）
2. 各章列出关键论点骨架
3. 向用户展示骨架，等待确认或调整

### Step 4: 逐章填充（Phase 3）

按依赖顺序（行业层 → 公司层 → 判断层 → 估值层 → 汇总层）逐章填充。

每章填充时：
- 先读取映射表中对应的 skill 产出
- 按模板中该章的结构规范组织内容
- 事实陈述后统一标注引用：`[S编号]`
- 证据状态单独一行标注，例如：`证据状态：[公司口径]` / `证据状态：[第三方事实]` / `证据状态：[推测]` / `证据状态：[未核实]`；不得与 `[S编号]` 混写
- 缺失数据标注 `[需要用户提供]` 或 `待确认 ⚠️`

### Step 5: 质量门控（Phase 4）

执行三轮校验（章节级 → 数据一致性 → 全局硬约束），汇总结果。

### Step 6: 预审版组装与审查（Phase 5）

组装 `06-ic-memo-review.md`，保留正文引用、证据状态、质量报告、冲突、缺口和未覆盖章节；完成格式校验后，只对该预审版运行 research-core audit，并按 `blocked` / `partial` / `ready` 合同停止或报告。

### Step 7: 获批后生成终版（Phase 6）

仅在用户明确“预审通过”或给予等价授权，并满足 Phase 6 所有前置条件后，重新组织获批信息形成临时候选；运行 `validate_final.py`，通过后发布 `06-ic-memo.md`。默认不执行本步骤。

## 硬约束

### 共同约束

- 风险逻辑与投资逻辑保持平衡：投资风险（第 3 章）篇幅 ≥ 投资亮点（第 2 章），风险条数 ≥ 亮点条数。
- 同一数据全文统一口径，不编造数据，不使用没有证据的修饰词。
- 不替用户写“建议投资”“不建议投资”“有条件投资”等最终 invest/pass decision（投资/放弃决策）；只呈现交易条件、收益情景、关键前提和待决事项。
- 中文输出，术语首次出现附中文解释；执行摘要最后回写。

### 预审版约束

- 所有数字可追溯到素材来源；正文保留引用和证据状态。
- 完整保留来源冲突、证据缺口、未覆盖章节、质量报告和需要用户裁定的事项。
- audit 的 `ready` 不等于用户批准；`partial` 未获用户明确接受、`blocked` 或无有效审查结果时不得生成终版。

### 终版约束

- 只使用获批预审版及用户裁定，不新增事实、数字或判断。
- 重新组织陈述而非机械删除标签；不完全确定但获准保留的信息必须使用概率、预计、约数、区间或情景表达。
- 不含来源、引用、页码引用、证据状态、研究状态、质量报告、缺口标签、占位符和内部操作说明；空章节省略。
- 必须先在临时路径通过 `validate_final.py`，再发布 `06-ic-memo.md`；失败不得覆盖已有终版。
