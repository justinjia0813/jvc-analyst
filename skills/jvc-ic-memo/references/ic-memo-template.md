# IC Memo 工程化生产指南

> 本文件既是模板，也是生产规范。每个章节包含：结构定义、内容标准、数据要求、质量门控。
> 遵循此文件可工程化生产一份达到 IC 审议标准的投决备忘录。
> 本模板每章出现的 source（来源）标注、证据状态和 checklist（检查清单）示例仅适用于预审版；批准后的终版执行「终版转换合同」。

---

## 0. 生产流程总览

```
Phase 1: 素材准备
  ├─ 收集原始材料（deck、招股书、访谈纪要、行业报告）
  ├─ 登记至 indexes/LLM-Wiki来源登记.md
  └─ 建立项目文件夹，归档原始材料

Phase 2: 骨架搭建
  ├─ 复制本模板，替换标的名称
  ├─ 填写执行摘要（先写交易概要，再倒推其他）
  └─ 列出各章节的关键论点骨架（每章 3-5 个要点）

Phase 3: 逐章填充（按依赖顺序）
  ├─ 行业概况 → 市场规模 → 产业链分析 → 竞争格局（行业层）
  ├─ 公司概况 → 产品矩阵 → 核心团队 → 核心壁垒 → 主要客户（公司层）
  ├─ 投资亮点 & 投资风险（判断层，依赖前两层）
  ├─ 收入预测模型 → 可比公司 → 投资回报模型 → 交易测算（估值层）
  └─ Cap Table（交易层）

Phase 4: 质量门控
  ├─ 数据一致性校验（同一数据在不同章节口径一致）
  ├─ 逻辑闭环检查（亮点-壁垒-风险 三角自洽）
  ├─ 来源标注完整性审计
  └─ 执行摘要回写（用全文结论更新摘要）

Phase 5: 预审版交付
  ├─ 生成 06-ic-memo-review.md
  ├─ 保留正文引用、证据状态、冲突、缺口、未覆盖章节和质量报告
  └─ 只将预审版交给 research-core audit，按状态停止或报告

Phase 6: 批准后生成终版
  ├─ 等待用户明确“预审通过”或等价授权
  ├─ 按用户裁定重新组织获批信息，生成临时候选
  └─ validate_final.py 通过后发布 06-ic-memo.md
```

### 质量红线（任何章节均适用）

| 红线 | 说明 |
|------|------|
| 不可编造数据 | 无来源数据标注「待确认 ⚠️」，不得虚构 |
| 数据标注来源 | 格式：`[S编号]` |
| 口径一致 | 同一指标全文统一口径（如收入含税/不含税） |
| 勾稽可验 | 财务数据之间可交叉验证 |
| 风险篇幅 ≥ 亮点篇幅 | IC 审议要求，风险不能走过场 |

### 终版转换合同

- 已确认信息使用确定性陈述；不完全确定但获准保留的信息使用概率、区间、“预计”“约”或“情景”等限定表达。
- 终版不带来源、引用、页码引用、证据状态、研究状态、质量报告、缺口标签、占位符或内部操作说明；空章节省略。
- 数字冲突必须先由用户裁定；仍有未裁定数字冲突时停止生成终版。
- 终版不得增加获批预审版没有的事实、数字或判断；需要新增时返回预审流程。
- 终版按用户裁定重新组织正文，不做机械标签删除，不能把未核实内容伪装成确定事实。

## 1. 执行摘要

> **定位**：IC 委员 30 秒内抓住核心信息的入口。最后写、最先读。

| 字段 | 内容规范 | 数据要求 |
|------|---------|---------|
| 标的 | 公司全称（简称） | — |
| 业务简介 | 4 行以内，覆盖：行业定位 / 核心产品 / 团队背景 / 商业化阶段 | 每行 ≤ 30 字 |
| 财务 | 3 行：去年实绩 / 今年预测 / 未来三年预测 | 收入 + 净利润，标注口径（含税/不含税、报表/管理口径） |
| 交易概要 | 2 行：本轮融资结构 / 退出预期 | 投前估值、融资金额、我方拟投金额、预期 IPO 时间、预期回报倍数 |

**模板**：

```markdown
## 执行摘要

| 标的   | [公司全称]（[简称]）|
| ---- | ---- |
| 业务简介 | - [一句话行业定位]<br>- [核心产品及技术路线]<br>- [创始团队核心背景]<br>- [商业化阶段：收入规模/客户数/产能利用率] |
| 财务   | - [去年]收入 [x] 亿元，净利润 [x] 亿元（[口径说明]）<br>- [今年]E 收入 [x] 亿元，净利润 [x] 亿元<br>- [未来三年] CAGR [x]%，[目标年]E 净利润 [x] 亿元 |
| 交易概要 | - 本轮为 [轮次] 融资，投前估值 [x] 亿元，拟融资 [x] 亿元，华胥拟投 [x] 万元<br>- 预计 [x] 年申报 IPO，按 [x]xPE 测算预期回报 [x] 倍 |
```

**质量门控**：
- [ ] 财务数据与「收入预测模型」章节一致
- [ ] 交易条款与「Cap Table」章节一致
- [ ] 回报倍数与「投资回报模型」章节一致
- [ ] 口径说明明确（含税/不含税、人民币/美元）

## 2. 投资亮点

> **定位**：回答「为什么要投」。每条亮点 = 一个独立的投资论点。

**结构规范**：先写一句概括性结论（加粗），再展开 2-3 段论据。

**必须覆盖的维度**（按重要性排序，可合并但不可遗漏）：

| # | 维度 | 内容指引 | 常见陷阱 |
|---|------|---------|---------|
| 1 | 政策/监管顺风 | 具体政策文件名称、发布时间、核心条款对标的的影响路径 | 不要只说「政策利好」，要说清利好传导机制 |
| 2 | 行业趋势与时机 | 行业处于什么阶段（导入/成长/成熟）、核心驱动因子、为什么是现在 | 避免罗列趋势不做判断，要说清「所以呢」 |
| 3 | 产品/技术竞争力 | 技术路线选择的合理性、产品性能参数对比、代际差异 | 避免自说自话——必须有竞品对比数据 |
| 4 | 团队竞争力 | 创始人履历的「相关性」而非「光环」、核心技术团队完整性、激励机制 | 避免「清华北大所以厉害」式论证 |
| 5 | 商业化进展 | 在手订单、签约客户、收入增速、复购率、pipeline | 区分「意向」和「签约」和「交付确认」 |
| 6 | 核心壁垒 | 技术壁垒/规模壁垒/网络效应/转换成本/品牌——选最强的 1-2 个展开 | 壁垒必须可验证，不能是「团队优秀所以有壁垒」 |

**模板**：

```markdown
## 投资亮点

**1. [一句话概括，如：钠电正极材料进入产业化拐点，政策与需求共振]**

[展开段落：政策背景 + 行业数据 + 传导逻辑]
[S编号]

**2. [一句话概括]**

[展开段落]

...
```

**质量门控**：
- [ ] 每条亮点有独立数据支撑（不是同一个论据换个说法）
- [ ] 亮点与「投资风险」章节形成对照（每个亮点背后有没有对应风险？）
- [ ] 不出现「行业前景广阔」「团队优秀」等空话

## 3. 投资风险

> **定位**：回答「为什么不投 / 投了可能亏在哪」。IC 委员最关注这一节。
> **硬性要求：篇幅不少于投资亮点。**

**结构规范**：与亮点对称——先一句概括性结论（加粗），再展开说明 + 缓释措施。

**必须覆盖的风险维度**：

| # | 风险类型 | 内容指引 |
|---|---------|---------|
| 1 | 技术风险 | 技术路线是否有被颠覆的可能、量产良率、工艺成熟度 |
| 2 | 市场风险 | 市场增速不及预期、下游需求变化、替代技术威胁 |
| 3 | 竞争风险 | 龙头降维打击、价格战、同质化 |
| 4 | 经营风险 | 客户集中度、供应链依赖、关键人风险、现金流 |
| 5 | 估值/退出风险 | 当前估值是否合理、IPO 窗口不确定性、退出路径受限 |
| 6 | 政策/合规风险 | 行业政策转向、环保/安全监管、出口管制 |

**每条风险必须包含**：
1. 风险描述（什么可能出错）
2. 影响量化（出错后损失多大）
3. 概率判断（高/中/低，需给出依据）
4. 缓释措施（公司有什么应对、我们有什么对冲）

**模板**：

```markdown
## 投资风险

**1. [风险概括，如：钠电技术路线存在被锂电快速降本挤压的可能]**

- 风险描述：[具体说明]
- 影响评估：若发生，可能导致 [量化影响]
- 概率判断：[高/中/低]，依据为 [xxx]
- 缓释措施：[公司层面] + [投资条款层面]
[S编号]

**2. [风险概括]**
...
```

**质量门控**：
- [ ] 风险数量 ≥ 亮点数量
- [ ] 每条风险有量化影响评估（不能只定性）
- [ ] 至少有一条风险涉及估值/退出
- [ ] 缓释措施具体可执行（不是「持续关注」）

## 4. 行业概况

> **定位**：让 IC 委员在 2 分钟内建立行业认知框架。

**必须回答的三个问题**：

| 问题 | 内容 |
|------|------|
| Where we are | 行业当前阶段、渗透率、技术成熟度、产业链成熟度 |
| Where we go | 3-5 年趋势判断、核心驱动因子、拐点信号 |
| What the path | 从现状到趋势的实现路径、关键里程碑、不确定性 |

**结构要求**：
- 开篇用 1-2 句话定义行业边界（做什么、给谁用、解决什么问题）
- 行业发展简史用时间线形式（关键节点，不超过 5 个）
- 当前阶段判断需有定量依据（渗透率、增速、政策节点）
- 趋势判断区分「确定性高的」和「存在分歧的」

**质量门控**：
- [ ] 行业定义边界清晰（读者能判断什么算、什么不算）
- [ ] 趋势判断有数据或逻辑支撑，不是「前景广阔」
- [ ] 与「市场规模」章节的增速假设一致

## 5. 市场规模

> **定位**：回答「这个生意能做多大」。

**硬性要求：必须同时提供 Bottom-up 和 Top-down 两套测算，交叉验证。**

### Bottom-up 测算规范

```
TAM = Σ (各细分应用场景 × 单价 × 渗透率)

需要拆解：
├─ 下游应用场景分类（穷尽且互斥）
├─ 每个场景的潜在客户数量 / 装机量 / 需求量
├─ 单价（当前价 + 趋势判断）
├─ 渗透率（当前 + 目标年预测）
└─ 得出各场景 TAM，汇总得全口径 TAM
```

### Top-down 测算规范

```
TAM = 上游市场规模 × 本环节价值占比
或
TAM = 宏观驱动指标 × 转化系数

需要标注：
├─ 上游/宏观数据来源（第三方报告名称、发布机构、日期）
├─ 价值占比 / 转化系数的依据
└─ 与 Bottom-up 的差异及解释
```

### 市场增长 Driver

- 列出 3-5 个核心增长驱动因子
- 每个 driver 需标注：影响方向（正/负）、影响量级（大/中/小）、确定性（高/中/低）
- 至少有 1 个「非共识」driver（市场可能忽视的）

**模板**：

```markdown
## 市场规模

### Bottom-up 测算

| 应用场景 | 潜在规模 | 单价（万元） | 渗透率（2026E） | 市场空间（亿元） |
|---------|---------|------------|----------------|----------------|
| 场景A   | xx 万台  | xx         | xx%            | xx             |
| 场景B   | ...     | ...        | ...            | ...            |
| **合计 TAM** | | | | **xx** |

[S编号]

### Top-down 验证

[上游市场规模] × [本环节价值占比] = [TAM]
[S编号]

### 两套测算对比

| 方法 | TAM（亿元） | 差异原因 |
|------|-----------|---------|
| Bottom-up | xx | — |
| Top-down | xx | [解释差异] |

### 核心增长 Driver

| Driver | 方向 | 量级 | 确定性 | 说明 |
|--------|------|------|--------|------|
| [driver1] | 正 | 大 | 高 | ... |
| [driver2] | 正 | 中 | 中 | ... |
| [driver3] | 负 | 小 | 低 | ... |
```

**质量门控**：
- [ ] 两套测算差异在 30% 以内，或差异有合理解释
- [ ] 渗透率假设有横向对比参照（类似行业的渗透率曲线）
- [ ] 单价趋势考虑了降本曲线
- [ ] 数据来源清晰（不接受「据估算」「约」等模糊表述用于核心假设）

## 6. 产业链分析

> **定位**：回答「价值如何在链条上分配，标的卡在什么位置」。

**结构要求**：

```
上游（原材料/设备/IP）
  → 中游（制造/加工/集成）
    → 下游（应用/终端客户）

每一层标注：
├─ 主要玩家（2-3 家代表性企业）
├─ 毛利率水平
├─ 议价能力（强/中/弱）
├─ 竞争格局（分散/集中，CR3/CR5）
└─ 标的在该层的位置（用 ★ 标记）
```

**必须回答**：
1. 标的在产业链中的议价地位如何？
2. 上下游是否存在被挤压的风险？
3. 是否有纵向整合的趋势？标的是受益还是受损？

**质量门控**：
- [ ] 产业链至少覆盖三层（上中下游）
- [ ] 标的位置明确标注
- [ ] 议价能力判断有依据（客户集中度、供应商替代性等）

## 10. 核心团队

> **定位**：回答「这帮人能不能把事做成」。

**必须覆盖**：

| 角色 | 必填信息 |
|------|---------|
| 创始人/CEO | 教育背景、行业经验年限、与本业务的相关性、过往创业/管理经验、持股比例 |
| CTO/技术负责人 | 技术背景、核心技术贡献、专利数量、团队规模 |
| 其他核心高管 | 分管领域、背景简介 |
| 团队整体 | 总人数、研发占比、核心团队稳定性、期权池设置 |

1. 创始人的行业 know-how 是否足够深（不是学历光环）
2. 技术团队能否支撑产品路线图的兑现
3. 商业化团队是否匹配目标客户群体
4. 股权结构是否有利于长期激励

**质量门控**：

## 11. 核心壁垒

> **定位**：回答「别人为什么做不了 / 做不好同样的事」。

**壁垒类型清单（选最适用的 1-3 个展开）**：

| 壁垒类型 | 判断标准 | 验证方式 |
