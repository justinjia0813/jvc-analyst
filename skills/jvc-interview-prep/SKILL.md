# 访谈提纲

回答“这次见面最该问什么、怎么问、听到什么说明判断要改”。交付一页能带进会议室的 `interview-prep-{对象}.md`。

## 适用级别

最低适用级别：**L0+**（有 BP、纪要或一句话疑点就能跑）。

## 输入

- 访谈对象和身份：创始人/管理层、客户、专家、前同事或推荐人、上下游。
- 已有材料：BP、以前的纪要、初筛、商业经济分析等（有什么用什么）。
- 这次最想搞清楚的事（可选）；没说就从材料里找最影响判断的 3–5 个疑点。
- 时长（可选）。

## 执行

1. 读 [题库与写法](references/question-bank.md)。
2. 从材料里挑出 3–5 个最影响投资判断的疑点，写成可被推翻的假设（例如“一轻控股的订单会在明年一季度验收回款”）。
3. 每个假设配 2–4 个问题，按对象选用题库里的问法。优先问发生过的事（最近一次、具体一次），少问意愿和评价。
4. 按时长排序：必问题放前面，时间不够时知道砍哪些。
5. 写明每个问题“听到什么算过关、听到什么要警惕”。

## 输出结构

```
# {对象}访谈提纲｜{日期}｜{时长}

## 这次要搞清楚的事（3–5 条假设，一句话各一条）

## 问题（按优先级）
### 假设 1：……
1. 问题（原话可直接念）
   - 想验证：……
   - 过关：……  警惕：……
   - 追问：……

## 需要对方会前或会后提供的材料

## 不该问或要换个问法的（可选）
```

总长控制在一页半以内，能打印带进会议室。

## 文件位置

用户指定路径优先；否则写进材料所在的项目或赛道文件夹根目录（不放进原始材料子目录）；都没有时问一次放哪。中间文件（JSON、转出的文本、计算脚本、证据台账）放在同目录的 `_work/`。同名文件已存在时不覆盖，加日期后缀。

## 反合理化约束

- 不问诱导性问题（“你们的产品是不是很受客户欢迎”），改问具体经历（“最近一次续约是怎么谈的，谁拍板的”）。
- 对创始人的判断看行为证据：具体情境、创始人本人做了什么、结果如何、归因范围多大；不问性格测试题，不以学历头衔代替能力。
- 客户访谈分清试点、合同、使用、验收、付款、复购各是哪一步，一次付款不等于持续使用。
- 只生成提纲，不代替用户联系任何人。
- 证据内核默认不启用。

## 完成

用户带着这份提纲进会议室，照着问完就能知道哪几个关键判断要改。
