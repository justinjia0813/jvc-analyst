# 访谈纪要版式合同

## 生成器与文件名

从本 skill 所在目录解析绝对路径，不依赖当前工作目录：

- 生成器：`scripts/generate_meeting_notes.py`
- 默认模板：`templates/访谈纪要模板.docx`
- 依赖：`requirements.txt`

生成器读 JSON（JavaScript Object Notation，JavaScript 对象表示法），字段为 `title`、`interviewee`、`filename`、`sections`；每个 section 有 `heading`，以及 `content` 或 `subsections`（每项含 `heading` 与 `content`）。

```bash
python3 "<生成器绝对路径>" "<data.json>" --output "<输出目录>"
```

文件名 `【YYYY年MM月DD日访谈】{访谈对象}.docx`，工作版为 `【YYYY年MM月DD日访谈】{访谈对象}（工作版）.docx`。口述日期中的斜杠转为年月日；日期或对象缺失时询问，不猜。只写新输出目录，不覆盖已有纪要。

模板优先级：`--template path/to/template.docx` → 环境变量 `JVC_DOCX_TEMPLATE` → 本地 `templates/custom.docx` → 中性默认模板。用户模板的页面、样式、页眉页脚保留；`templates/custom.docx` 已被 git 忽略，放机构模板不会误提交。

## 六段式（默认）

1. 公司基本情况
2. 公司核心技术
3. 公司核心团队
4. 公司核心产品
5. 商业化进展（成本、毛利、现金流、订单等财务内容放在本段的财务小节）
6. 融资情况

重要原话、数字、条件、矛盾放进对应章节。材料没有涉及的章节写“本次访谈未涉及”。整理完按原问题逐项核对去向，避免漏掉只被问了一次的内容。

## 问答式

1. 访谈基本信息（日期、形式、对象及身份、我方参与人）
2. 问答纪要：每题一个 subsection，`heading` 写 `Qn：问题原意`；`content` 是完整回答，保留信息强度和说话人身份，不压缩成一句摘要
3. 用户观察（来自随笔，和受访者说法分开）

交付版到此为止。工作版在问答的每题 `content` 末尾追加两行：

- `【对应事实层维度】`：公司、技术、团队、产品、商业化、融资、客户、财务、风险中的相关项；
- `【待验证点】`：回避、矛盾、数字不清或需要外部证据的地方；没有就写“无明显疑点”。

并在文末追加：事实层索引、后续追问清单、名称对照表、自查修改记录。

## 多段录音合并

同一天多段访谈（如上午管理层、下午实验室现场）默认合并为一份纪要：一级章节按场次分（“一、上半场（公司层面）”“二、下半场（实验室现场）”），问答编号全篇连续。合并后逐项核对：章节编号不断档、问题编号不跳号、标题日期是访谈日而非随笔日期。

## 交付前检查

- 生成后渲染全部页面，检查缺字、裁切、层级、间距、页眉页脚。无法渲染时说明未做视觉检查。
- 核对：说话人没有张冠李戴；问答边界清楚；关键数字与原文一致；交付版没有混入工作版的待验证点。
- 修改后重新生成，不手工拼接旧文件。
