# 指标口径与预警规则

## 取数口径

| 指标 | 取自 | 口径说明 |
| --- | --- | --- |
| 营业收入 | 利润表“营业总收入”或“营业收入” | 季报给本期金额和本年累计；月报给本月和本年累计。单季 = 本期累计 − 上期累计 |
| 毛利率 | (营业收入 − 营业成本) ÷ 营业收入 | 单季和累计分开算 |
| 净利润 | 利润表“净利润” | 注明是否含少数股东损益 |
| 经营现金流 | 现金流量表“经营活动产生的现金流量净额” | 单季同样用累计相减 |
| 期末可用现金 | 资产负债表“货币资金” | 扣除已知受限资金（保证金、质押）；不知道是否受限时注明 |
| 月均净消耗 | 近 3 个月（或本季）经营现金流 + 投资现金流中的维持性支出，取负值部分 ÷ 月数 | 产线建设等一次性资本开支单列，不混进日常消耗 |
| 日常消耗参考月数 | 期末可用现金 ÷ 月均净消耗，仅在净消耗为正时计算 | 仅作参考，不能代替含建厂、还款的逐月预测 |
| 应收周转天数 | 平均应收余额 ÷ 单季收入 × 本季天数 | 缺期初余额时注明使用期末余额近似 |
| 存货周转天数 | 平均存货余额 ÷ 单季营业成本 × 本季天数 | 分母为成本；分母为零或资料缺失时不计算 |

小企业会计准则报表（“会小企”）和企业会计准则报表的科目名称略有不同，按实际科目取数并在附注写明。

## 默认预警规则

用户仪表板或投资协议里有自己的规则时，以用户的为准。

| 信号 | 默认触发条件 |
| --- | --- |
| 现金紧张 | 基准逐月预测在 9 个月内触零；未到账融资不解除预警 |
| 现金危急 | 基准逐月预测在 6 个月内触零 |
| 收入落后 | 本年累计收入 < 年度目标 × 已过时间比例 × 70% |
| 毛利恶化 | 单季毛利率较上季下降超过 10 个百分点，或连续两季下降 |
| 回款变差 | 应收增速明显快于收入增速（超过 1.5 倍） |
| 存货积压 | 存货增速明显快于收入增速，且产线处于爬坡期以外 |
| 里程碑延迟 | 任一里程碑超过计划时间仍未完成，或管理层已表示将延后 |
| 亏损扩大 | 单季净亏损较上季扩大超过 30%，且收入没有同比例增长 |
| 关键人员变动 | 管理层汇报或公开信息显示核心团队离职 |

触发信号只说明“需要关注”，写清数字和规则，不等于风险已经发生。

## 现金预测与现金跑道

基准期末余额 = 上期可用现金 + 当期经营净现金流 − 资本开支 − 到期还本付息 + 其他净现金流。

1. 截止日货币资金扣除受限资金，得到期初可用现金。截止日已到账融资已包含在该余额，不能再加一次。
2. 至少覆盖未来 12 个月及下一里程碑；若资料只支持较短期间，明确实际覆盖月份。期间按连续自然月排列。经营净现金流不得重复包含单列的资本开支和债务支出；若原报表将利息列入经营流，先从经营净额还原，再计入还本付息。金额使用同一币种和单位。
3. 所有未来融资、未到账补助均为条件情景，包括已签协议尚未到账的融资。单独写到账月份和条件。基准情景不计这些钱。
4. 记录首次月末余额 ≤ 0 的月份、里程碑前最低余额，以及最低补足缺口 `max(0, -最低余额)`。这不含安全垫；月末余额为正也不能证明月内没有支付缺口，重大支付应进一步按日检查。
5. 缺少资本开支、还款或受限资金信息时写“现金预测不完整”，不能把未知填 0。已确认没有该项才填 0。经营净现金流为正不代表偿付能力充足。

输入格式见仓库 `examples/portfolio-cash-input.json`。把本次输入存入项目 `_work/cash-input.json`，从 Skill 实际目录解析脚本并执行：

```bash
python3 "<skill-root>/scripts/cash_runway.py" "<project>/_work/cash-input.json" > "<project>/_work/cash-result.json"
```

`cash` 为截止月末货币资金，`restricted_cash` 为受限部分。`periods` 每月必填 `operating_net`、`capex`、`debt_service`、`other_net`；流出专列用正数，净现金流允许负数。`financing_scenarios` 的 `inflows` 以月份为键；`milestone_month` 必须在预测范围内。只有退出码 0 才引用计算结果。
