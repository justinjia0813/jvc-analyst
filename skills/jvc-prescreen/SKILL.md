# 项目初筛

30 分钟内回答“这个项目值不值得花时间见创始人、深入看”。交付 `01-prescreen.md`，读者是合伙人。

## 适用级别

最低适用级别：**L0+**（只要有一份 BP 或几段项目介绍就能跑）。L0 不初始化证据内核，不建 `spec/` 目录。

## 输入

BP / deck、公开链接、转发来的项目介绍、用户的初步印象，任意组合。

## 执行

1. 先抓事实：公司、阶段、团队、产品、客户、收入/订单、融资历史、本轮条款。每个关键数字标来源（`[BP p.N]`、`[创始人自述]`、`[公开新闻: 来源 日期]`）。
2. 七维度过一遍，每个维度给一句判断，而不是只列“缺什么”：

   | 维度 | 核心问题 |
   | --- | --- |
   | 市场 | 多大、增长靠什么驱动 |
   | 痛点 | 是否真实、紧迫、有人愿意付钱 |
   | 方案 | 技术/产品是否成立，和现有做法差在哪 |
   | 团队 | 为什么是这群人能做成 |
   | 时机 | 为什么是现在 |
   | 商业模式 | 怎么赚钱，单位经济大概是正是负 |
   | 显性风险 | 一眼能看到的硬伤 |

3. 缺数据时用有依据的估算补齐，标 `[估算：依据]`；实在无从判断的写“看不出”，放进问题清单。
4. 写出最可能让这个项目不成立的 2–3 个理由。
5. 列见创始人前要问的 3–5 个问题。需要完整提纲时交给 `jvc-interview-prep`。

## 输出结构

```
# {公司}：初筛｜{日期}

## 一句话判断
（3–5 句：这是一家什么公司、最值得看的一点、最担心的一点、下一步建议看什么。不写投/不投。）

## 基本面
（一张表：公司/成立/阶段/团队/产品/客户与收入/融资历史/本轮条款）

## 七维度
（一张表：维度｜判断｜依据｜信心 高/中/低）

## 最可能不成立的理由
（2–3 条，每条一句话加论据）

## 见创始人前要问的问题
（3–5 条，可直接问）
```

全文控制在两页以内。

## 文件位置

用户指定路径优先；否则写进材料所在的项目或赛道文件夹根目录（不放进原始材料子目录）；都没有时问一次放哪。中间文件（JSON、转出的文本、计算脚本、证据台账）放在同目录的 `_work/`。同名文件已存在时不覆盖，加日期后缀。

## 反合理化约束

- 创始人背景强不等于能做成；写具体做过什么、结果如何。
- 市场大小要有口径和数字；拿不到就给估算区间并标依据，不用“万亿级”一类形容词。
- 不写“建议投资/不建议投资/值得关注”这类终局判断；可以写“最值得验证的是 X”。
- 不用没有支撑的修饰词（领先、颠覆、护城河）。

## 完成

合伙人读完一句话判断，就知道这个项目是什么、为什么可能值得看、最担心什么；读完问题清单，就知道第一次见面该问什么。
