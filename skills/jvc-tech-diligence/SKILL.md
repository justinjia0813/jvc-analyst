# 技术尽调

回答“这家公司宣称的技术能不能成立、比现有最好方案好在哪里、离可量产还差什么、哪几个参数一旦查清就能定性”。默认交付 `03-tech-diligence.md`。

## 适用级别

最低适用级别：**L1+**（至少有一条明确的技术宣称和一份支撑材料：BP 技术页、论文、专利、测试报告或访谈纪要）。

## 输入

- 技术宣称（必需）：BP 或访谈里公司自己怎么说，原话优先。
- 支撑材料（至少一项）：论文、专利、第三方检测报告、客户验证报告、样品数据、访谈纪要。
- 对标对象（可选）：用户已知的竞品或主流方案；没给就自己检索公开资料确定。
- 用户的专业背景和最担心的点（可选），用来决定追问深度。

## 执行

1. 读 [检查清单](references/checklist.md)。原始材料只读。
2. **拆宣称。** 把每条技术宣称拆成“参数 + 数值 + 测试条件 + 规模”（例如“硅碳负极首效 90%” → 首次库伦效率 90%，扣式半电池，0.1C，克级样品）。测试条件或规模缺失的，标 `[条件未披露]`，转成待问问题。
3. **原理判断。** 用物理、化学或工程原理解释为什么可能成立、上限在哪里。宣称接近或超过理论极限、或与已知规律矛盾时，写明矛盾点和需要什么证据才能解释。
4. **对标最优水平。** 列关键参数对比表：公司宣称、主流量产方案、公开报道的最优水平（论文或竞品），每个数字标来源和测试条件。条件不同的数字不直接比较，写明差异。
5. **成熟度分段。** 按实验室 → 中试 → 量产判断当前所处阶段，指出下一段最难跨过的工程问题（一致性、良率、成本、设备、供应链、认证周期），以及跨过它通常需要的时间和资金 `[估算：依据]`。
6. **找落差。** 对照宣称与证据：哪些只有公司自述、哪些有第三方数据、哪些数据与宣称的口径不一致。专利只说明“申请了什么”，不等于“做到了什么”；论文结果不等于公司产线结果。
7. **出问题。** 写 5–8 个最该问创始人或技术专家的问题，按对投资判断的影响排序，每题写“听到什么算过关、听到什么要警惕”。要进会议室时交给 `jvc-interview-prep`。

## 输出结构

```
# {公司}：技术尽调｜{日期}

## 技术判断（3–5 句：能否成立、相对最优水平的真实位置、离量产的最大障碍、最可能错在哪）

## 宣称拆解
| 宣称（原话） | 参数 | 数值 | 测试条件 / 规模 | 证据类型 |

## 原理与上限

## 关键参数对标
| 参数 | 公司宣称 | 主流量产 | 公开最优 | 可比性说明 |

## 成熟度与下一道坎
- 当前阶段：实验室 / 中试 / 量产，依据……
- 下一道坎：……  需要的时间与资金：[估算：依据]

## 宣称与证据的落差

## 最该问的技术问题（按影响排序，含过关与警惕信号）

## 最可能错在哪（1–2 个会推翻判断的因素及临界值）

## 依据（来源清单，附录）
```

## 文件位置

用户指定路径优先；否则写进材料所在的项目或赛道文件夹根目录（不放进原始材料子目录）；都没有时问一次放哪。中间文件（JSON、转出的文本、计算脚本、证据台账）放在同目录的 `_work/`。同名文件已存在时不覆盖，加日期后缀。

## 反合理化约束

- 不把实验室数据当量产能力，不把小样品、单批次、扣式电池或流片样片的结果外推到产线，外推时写清假设。
- 不比较测试条件不同的数字；比较不了就写“口径不同，无法直接比较”。
- 专利数量不是技术壁垒的证据；看权利要求覆盖什么、权属是否清晰（权属和 FTO 风险交给 `jvc-dd-report-digest` 的法律尽调清单）。
- 论文作者是创始人，不代表公司已掌握论文中的工艺；要问哪些在公司产线上复现过。
- 计算（能量密度、成本、良率影响）实际执行，不心算。
- 不替用户下“技术不行 / 技术领先”的终局结论；写“在什么条件下成立、什么数据会推翻”。
- 证据内核默认不启用；用户要求 `--rigor` 时按 [调用合同](../jvc-research-core/references/caller-contract.md) 以 `jvc-tech-diligence` 身份审查。

## 完成

合伙人读完技术判断，就知道这项技术真实处在什么位置、离赚钱还差哪道坎、下一次见面该追问哪个参数。
